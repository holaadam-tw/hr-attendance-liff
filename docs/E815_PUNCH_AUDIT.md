## 4. 修正的系統缺陷（migration 106）

補打卡驗證原本**只檢查日期、完全不檢查時間**，是上述 (1)(2) 兩筆壞資料的共同成因。

| 檢查項目 | 修正前 | 修正後 |
|---------|-------|--------|
| 日期不得為未來 | ✅ | ✅ |
| 日期 7 天窗口（員工端）| ✅ | ✅ |
| **當天補卡時間不得晚於現在** | ❌ 無 | ✅ `punch_time_in_future` |
| **下班不得早於當日上班** | ❌ 無 | ✅ `checkout_before_checkin` |
| **上班不得晚於當日下班** | ❌ 無 | ✅ `checkin_after_checkout` |

範圍涵蓋 `submit_makeup_punch`（員工自助）與 `admin_makeup_punch`（管理員代補）兩支。
前端 `common.js submitMakeupPunch()` 另加同樣的「未來時間」即時提示（新增 `getTaiwanTimeHM()` helper）。

安全性查證：正式庫**無跨夜班員工**（`fixed_shift_end <= fixed_shift_start` 共 0 人），故「下班早於上班」的檢查不會誤擋正常班別。
