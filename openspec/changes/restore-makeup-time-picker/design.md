## Context

`records.html` 的補打卡時間使用文字輸入，確保所有裝置清楚顯示 `17:00`，但失去原生 `type=time` 的時鐘選擇入口。修正必須提供方便的選取方式，不能退回會受裝置地區格式影響的可見原生時間欄位。

## Goals / Non-Goals

**Goals:**

- 提供明確可點擊、具無障礙名稱的時鐘按鈕。
- 透過原生時間選擇器帶入有效的 `HH:mm` 值。
- 選取後立即執行既有的手動輸入、預設值與上下班時間衝突檢查。

**Non-Goals:**

- 不改補卡時間規則、預設值、資料庫、RPC、LINE 或排程。
- 不以裝置的 12 小時格式直接顯示實際提交值。

## Decisions

1. **保留可見的文字欄位。** `mpTime` 繼續顯示固定 `HH:mm`，讓 Android／LINE 的畫面不會再將下午 5 點誤讀為 `5:00`。

2. **新增隱藏的原生 `time` 控制項及可見時鐘按鈕。** 按鈕由使用者手勢直接呼叫 `showPicker()`；不支援的瀏覽器退回 `focus()`／`click()`。原生控制項只負責選取，不作為使用者可見的值。

3. **選取視同手動修改。** 選取後寫回 `mpTime`、取消自動預設旗標並呼叫 `onMpFormChange()`，所以已知的上班／下班時間衝突會立即顯示且停用送出。

## Risks / Trade-offs

- [部分 WebView 不支援 `showPicker()`] → 退回原生 `click()`，手動輸入仍可使用。
- [隱藏 input 未同步] → 每次開啟前與選取後都用既有正規化函式同步 `HH:mm`。
- [時鐘按鈕誤被視為送出表單] → 按鈕明確指定 `type="button"`。

## Migration Plan

1. 只修改前端表單與回歸測試。
2. 瀏覽器／手機檢查時鐘按鈕、選取結果、17:00 顯示及衝突提示。
3. 回復時還原 `records.html` 與測試；不涉及資料庫回復。
