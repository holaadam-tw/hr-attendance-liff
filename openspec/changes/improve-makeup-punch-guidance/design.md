## Context

`records.html` 的月曆以 `get_monthly_attendance` 載入員工自己的資料，但 `getStatus()` 目前只判斷該日是否存在 attendance；只要存在就可能回傳 `ok`，沒有檢查 `check_in_time`／`check_out_time` 是否完整。補打卡表單則沒有類型相關的預設時間，也沒有利用已載入的月曆資料先做同日時間衝突提示。

現有 migration 106 已在 `submit_makeup_punch` 強制驗證上下班先後順序，這是防止 05:00／17:00 誤填造成壞資料的最後防線，必須保留。

## Goals / Non-Goals

**Goals:**

- 讓過去日期的不完整打卡在月曆與補打卡頁都能被看見。
- 讓員工從待補項目一鍵帶入日期與上下班類型。
- 下班補卡預設使用公司 `default_work_end`，無有效設定時使用 17:00。
- 在送出前以已載入的 attendance 顯示「17:00 早於 19:52」等可理解提示。
- 免打卡人員不因整日無紀錄被要求補卡，但已存在的單邊打卡仍要提示補齊。

**Non-Goals:**

- 不修改 migration 106、RLS、資料表或正式資料；migration 116 只修正既有每日考勤 RPC 的免打卡篩選。
- 不自動送出、核准或覆寫任何補打卡／attendance。
- 不把排班時間宣稱為實際離班時間；17:00 只是可修改的預設值。
- 不允許員工用下班補卡修正一筆錯誤的既有上班卡；此類資料由主管代補覆寫。

## Decisions

1. **依身分選擇安全的提示資料來源。** `getStatus()` 新增 `missing_in`／`missing_out`，過去日期缺其中一側即列為待補；當天只有上班卡仍視為上班中，避免下班前誤報。單一公司的一般員工沿用既有 `get_monthly_attendance`；平台管理員、管理員與主管則對補卡期限內各日呼叫既有 `get_company_daily_attendance`，同時傳入目前公司與 LINE 呼叫者，並只保留 `employee_id === currentEmployee.id` 的資料。無法使用任一安全路徑時顯示限制說明，不回退到無公司範圍的資料。
   - 此修正沿用 migration 100 已部署的公司／主管權限驗證，不新增 RPC、migration 或資料表。

2. **待補清單只做導引，不作資料事實來源。** 清單由目前載入月份、既有請假判斷與補卡歷史組合；後端 RPC 仍是提交規則的唯一裁決者。
   - 已有 pending／approved 同日期同類型申請時，清單顯示狀態而不提供重複送出按鈕。

3. **下班預設時間只在尚未手動輸入時帶入。** 優先讀 `default_work_end`，格式無效時使用 `17:00`。為避免 Android 原生 `type=time` 依地區設定只畫出沒有 AM／PM 的 `5:00`，欄位改為受格式驗證的數字文字輸入，固定呈現 `HH:mm`；提示明示下午 5 點應填 `17:00`。切換成上班補卡不強制填入新的時間。

4. **前端衝突提示不取代資料庫驗證。** 若選定日期已有上班時間，且下班補卡時間小於或等於該時間，停用提交並顯示需主管先更正既有上班紀錄；`submit_makeup_punch` 的 migration 106 驗證保持不變。

5. **補打卡頁的長錯誤提示必須換行。** `style.css` 的共用 toast 預設為單行省略，本頁以局部樣式覆寫成手機寬度內換行，避免影響其他頁面版面；共用 `showToast()` 依文字長度將長訊息停留時間延長為 6 秒。

6. **免打卡只排除整日無紀錄。** 待補清單以員工資料的 `no_checkin === true` 為唯一免打卡依據，不以 `admin`／`manager` 角色推定。免打卡人員整日沒有 attendance 時不建立上下班待補項目；若已有上班或下班其中一側，仍保留缺少另一側的導引，避免既有不完整紀錄持續影響考勤。

7. **每日考勤 RPC 必須保留免打卡人員的既有打卡。** migration 100 原本以 `no_checkin=false` 直接排除整名員工，使前端無法看到免打卡人員已存在的單邊紀錄。migration 116 將條件限縮為：一般員工照常回傳；免打卡人員只有在 `check_in_time` 與 `check_out_time` 都為空時排除。RPC 簽章、`has_company_access(..., true)`、`company_id` 隔離、回傳欄位與其他狀態規則保持不變。

## Risks / Trade-offs

- [目前員工月曆 RPC 是按月份載入且沒有公司參數] → 單一公司員工沿用月曆 RPC；具管理權限者改用公司範圍每日 RPC。沒有管理權限的多公司一般員工仍顯示安全限制，後續若獲授權可新增公司隔離的員工自查 RPC。
- [17:00 可能不是實際離班時間] → 明示為可修改預設值，保留「請填實際時間」文字與主管審核。
- [既有 19:52 上班資料可能本身錯誤] → 不自動猜測或覆寫，顯示主管處理指引。
- [當天尚未下班被誤列] → `missing_out` 僅對早於今天的日期成立。
- [每日總覽原本完全隱藏免打卡人員] → 只有該日已存在打卡時才重新顯示；沒有任何打卡的免打卡人員仍不出現在總覽。

## Migration Plan

1. 在 `dev` 新增 migration 116 與資料來源回歸測試，不修改既有已執行 migration。
2. 套用前核對隔離測試 Project Ref 必須是 `vtlvjbwqrvhfgivbmmaa`，且不得等於正式 `nssuisyvlrqnqfxupklb`。
3. 驗證免打卡＋整日無卡不回傳、免打卡＋只有上班或只有下班會回傳、一般員工行為不變、跨公司／無權呼叫仍被拒絕。
4. 驗證後保留 migration 116 函式定義；如需回復，將 migration 100 的原函式定義以新回復 migration 重新套用，不刪除既有 migration。
